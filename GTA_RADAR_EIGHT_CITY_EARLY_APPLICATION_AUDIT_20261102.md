### Key architectural gap

The eight-city *meeting-index* count is **not** the number of cities ingesting new planning applications. Current code supplies partial official records for Toronto, Brampton and Mississauga, with different archive/integration paths. The other five city planning-application feeds are not fully connected to the daily first-seen/new-project pipeline. Current PDF capture across seven non-Toronto cities is **bounded and its real-world access remains unverified**.

## Best near-term sequence; avoid redundant engineering

1. **Brampton + Mississauga + Toronto**: inspect existing collectors, determine which application IDs are already in the DB or separate source archive, measure missed official active applications, and connect **only the missing feed/fields** into the daily publication-aware identity ledger. Do not run a parallel collector to count the same project twice.
2. **Oakville + Burlington**: public, directly readable application detail and ward pages. Test access, page hash change tracking, application IDs, commercial fit, and whether dates represent filing, update or meeting; connect as new data sources where not already covered.
3. **Kitchener + Hamilton**: evaluate production GIS public APIs, stable application IDs and true reported source dates. Ensure feature ObjectID is not presumed equivalent to a new application.
4. **Vaughan**: official PLANit mapping technology appears highly suitable, but determine permitted production source and application ID fields before enabling.
5. After getting early applications working for these eight, extend same approach to **Markham → Oshawa → Milton → Halton Hills**, prioritized in [GTA_RADAR_MUNICIPAL_EXPANSION_RESEARCH_20261102.md](GTA_RADAR_MUNICIPAL_EXPANSION_RESEARCH_20261102.md).

### Same evidence-first, AI-heavy policy

- **Code first:** poll official records or changed pages cheaply; record file ID, document URL, published filing date if given, last update, hash, and actual Radar observed timestamp **separately**.
- **AI on substance:** read supporting staff reports, unstructured application descriptions, scope, companies, phase, trade implications. Require original page/PDF evidence for claims.
- **Match identities carefully:** exact municipal file ID first; manually review address-only, re-numbered, multiple GIS feature or approximate company matches.
- **Never infer first public announcement:** stage date, applicant submission date, meeting date, site update date and collector first-seen are distinct.
- **No paid AI for HTML fetching or maps:** use the shared **US$0.25/day** DeepSeek ledger only for unstructured extraction and deeper qualified-source research. Any deferred work retains a persistent queue.
- **No verified buyer/outreach claims:** public applicant/consultant contact is **not** necessarily owner, operator, purchasing authority or a tender.

### Minimum acceptance test for each original municipality

Verify in a live Windows run: correct production official URL; permitted robots and terms; one genuine current OPA/ZBA/site plan application with exact municipal ID and original address; received date distinct from observed date; 2-run idempotence; a verified source report/attachment where public; AI extraction grounded in quotes; reproducible project identity join; an explicit commercial false-positive review; status exposed in daily dashboard.
